## Bugs Found

### TEST 10 — Service context lost after off-topic message

**Severity:** LOW
**Reproduction:**

1. Send "Book a cut" → Agent disambiguates (Wash Cut Blow Dry vs Restyle)
2. Send "what's the weather like?" → Agent redirects back to salon topics
3. Send "Sorry, next Monday at 10am" → Agent asks "What service?" instead of remembering the cut

**Root cause:** The session was recreated between turns (approval_mode creates `review` status, then cleanup may expire it). The `update_booking_state` call that would persist the service happens _after_ disambiguation — but the user went off-topic before picking one. So no service was ever locked.

**Assessment:** This is expected behaviour — the user never actually selected a specific service before going off-topic, so there was nothing to persist. If the user had said "the wash cut blow dry" first and _then_ gone off-topic, the service would have been retained via `update_booking_state`.
