## Bug Fixed During This Session

### Root Cause: `callAI` duplicated the last message in Gemini history

**File:** `lib/ai.ts`

The function built the Gemini chat history from **all** messages, then called `sendMessage(lastMessage.content)` — sending the last message twice. After a tool call, the second `callAI` invocation would end up with two consecutive `user`-role messages (the prior user message in history + the tool result sent as a new user turn), with no `model` turn in between. Gemini 2.5-flash returned an invalid/empty response in this state, triggering the `"I'm having trouble processing that."` fallback.

**Fix:** History is now built from `messages.slice(0, -1)`. System/tool result messages are prefixed with `[Tool Result]` when sent via `sendMessage` so the model understands context.

**Commit:** `53b887b`

## Next Steps / Review

### Prompt / Agent Behaviour

- **Check availability before collecting details** — Currently the agent asks for date + time, then name + email, and only then checks availability. It should check availability first (once date is known), confirm a slot exists, and only then ask for name and email to hold it. This avoids collecting personal info for a slot that doesn't exist.
- **Convert minutes to conversational language** — Agent currently says "150 minutes". It should say "2 hours 30 minutes" (and similarly "1 hour", "1 hour 15 minutes", etc.) for a more natural SMS tone.
- **Handoff notification** — When the agent says "Let me get the team to help you with this", how is the team actually notified? Need to decide: Slack message, email alert, dashboard flag, or a combination. Currently `handoff: true` is returned in the API response and the session is marked `handed_over` in the DB — but no outbound notification is sent.

### Infrastructure

- **Cal.com calendar setup** — DONE. Eduard, Sophia, and Vicky's calendars have working hours and availability configured.
- **Cancel booking tool** — NOT IMPLEMENTED. The system prompt tells the agent it can cancel appointments, but there is no `cancel_booking` tool declared in `lib/ai.ts` and no function in `lib/booking_service.ts`. The agent will try to cancel and fail silently. Needs a Cal.com DELETE `/bookings/{uid}` call + DB status update to `cancelled`.
- **Reschedule booking tool** — NOT IMPLEMENTED. No dedicated reschedule flow exists. Current approach would be cancel + rebook (two separate tool calls). Acceptable for now but worth a dedicated tool later for a smoother UX.
- **Held booking expiry cron** — `expires_at` is set to 10 minutes on each hold but no automated job cleans up stale `held` bookings. Slots could remain blocked indefinitely if the customer ghosts.
- **Twilio webhook** — Postponed.
